- the release blockers listed in the open-source release plan are closed
- the public docs match the actual runtime behavior

## 4. Preflight Verification

Run from the repository root:

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm bench:all
```

Run the example workspace path one command at a time.
Do not overlap multiple CLI commands on the same local SQLite during this publish check.

```sh
cd examples/minimal-director-angel-workspace
export HOTFLOW_WORKSPACE_ROOT="$PWD"
export HOTFLOW_DATA_DIR="$PWD/.hotflow"
pnpm --dir ../../apps/cli dev -- doctor --json
pnpm --dir ../../apps/cli dev -- run "Read README.md and summarize this workspace."
pnpm --dir ../../apps/cli dev -- golden-path README.md
pnpm --dir ../../apps/cli dev -- resume <sessionId>
```

Use the `sessionId` printed by `golden-path` when you run `resume`.

Minimum expected outcome:

- `doctor` succeeds
- `run` produces a valid response
- `golden-path` produces a recoverable session id
- `resume` reopens the printed session id successfully

## 5. GitHub Publication Steps

When it is time to actually publish:

1. Log into the `hotflow123` GitHub account.
2. Create the public repository under `hotflow123`.
3. Push the default branch.
4. Verify the repository homepage, description, and topics match `Director Angel OS`.
5. Create the first GitHub Release from the prepared `v0.1.0` notes.

## 6. Release Boundary

The first public release should say exactly what this repo is today:

- it is a role-driven Agent OS
- the current public content demonstrates Director responsibilities
- it already includes session runtime, tool execution boundaries, control plane, memory boundaries, and a controlled learning lane
- the future direction is custom user-defined positions with explicit responsibility boundaries
- it is not an unbounded self-modifying runtime
