# Director Angel 桌面端 UI 界面图谱

版本：v0.1  
参考布局：Codex App 三栏工作台  
目标：让用户能看见 Angel 如何学习、审查、晋升经验，并确认这些经验是否进入运行时。

## 2. Codex App 对应关系

| Codex App 区域 | Director Angel 桌面端对应 | 作用 |
| --- | --- | --- |
| 工作区/会话列表 | 左侧模式、来源、运行会话 | 让用户切换任务和学习来源 |
| 主对话区 | 中央对话执行流 + 底部 composer | 用户和 Angel 协作的主场 |
| Plan / Context 面板 | 右侧 Inspector | 显示计划、经验候选、召回证据、审核门 |
| 工具执行反馈 | 对话流中的系统消息 | 告诉用户当前学习/晋升/召回结果 |
| Diff / Review 面板 | 经验候选审查面板 | 决定经验是否可信、是否晋升 |

## 4. 主要界面状态

### 4.1 空状态

```text
左侧：没有学习来源
中间：提示用户选择桌面目录或输入搜索主题
右侧：计划步骤全部 pending
```

用户动作：

- 添加桌面目录
- 输入网页 URL
- 输入搜索主题

### 4.2 已学习但未审查

```text
左侧：学习来源显示候选数量
中间：Angel 报告“已生成经验候选”
右侧：经验候选状态为 candidate
```

用户动作：

- 查看证据
- 接受候选
- 拒绝候选

### 4.3 已接受但未晋升

```text
左侧：当前会话标记 reviewed
中间：显示“可晋升为正式知识候选”
右侧：审核门 Learning Review = pass
```

用户动作：

- 晋升知识
- 继续补充证据

### 4.4 已发布且可召回

```text
左侧：运行会话标记 recall hit
中间：系统消息显示“进入 execution.knowledge”
右侧：召回面板显示命中原因和分数
```

用户动作：

- 运行评估
- 查看隐藏提示摘要
- 回滚知识

## 5. 中央工作台结构

```text
┌ 顶部状态栏 ───────────────────────────────────────────────┐
│ Run / 会话标题 / 刷新 / 运行评估                              │
└──────────────────────────────────────────────────────────┘

┌ 对话执行流 ───────────────────────────────────────────────┐
│ 用户：让 Angel 学习经验                                     │
│ Angel：生成经验候选，默认不注入运行时                         │
│ 系统：发布后命中 global self-learning experience             │
└──────────────────────────────────────────────────────────┘

┌ 底部 composer ────────────────────────────────────────────┐
│ +  告诉 Angel 下一步要做什么                    [发送]       │
│    [目录学习] [网页主题] [候选审查] [运行时召回]              │
└──────────────────────────────────────────────────────────┘
```

## 6. 右侧 Inspector 标签

### 6.1 计划

显示：

- 候选数量
- 已发布知识数量
- 当前召回状态
- 当前步骤：读取来源、生成候选、接受晋升、进入 evaluate

### 6.2 经验

显示：

- 候选标题
- candidate id
- 来源类型
- 当前状态：candidate / accepted / promoted / published
- 操作：接受、拒绝、晋升、回滚

### 6.3 召回

显示：

- 命中的 knowledge pack id
- 命中原因
- score
- tags
- 是否进入 `execution.knowledge`
- 审核门：Learning Review、Knowledge Publish、Runtime Recall

## 7. 核心操作流

```text
选择学习来源
  ↓
运行 learn
  ↓
生成 ExperienceCandidate
  ↓
查看证据
  ↓
接受候选
  ↓
promote 为 DirectorKnowledgeCandidate
  ↓
knowledge accept
  ↓
knowledge publish
  ↓
Director evaluate
  ↓
published knowledge recall hit
  ↓
进入 execution.knowledge
```

## 8. 第一版按钮清单

| 位置 | 按钮 | 对应能力 |
| --- | --- | --- |
| 中央顶部 | 运行评估 | `director evaluate` |
| 底部 composer | 目录学习 | `knowledge learn --directory` |
| 底部 composer | 网页主题 | `knowledge learn --query` |
| 对话流 | 接受候选 | `knowledge experience-accept` |
| 对话流 | 晋升知识 | `knowledge experience-promote` |
| 右侧经验 | 拒绝候选 | `knowledge experience-reject` |
| 右侧召回 | 查看召回 | `knowledge recall-preview` |

## 9. 视觉规则

- 不做营销首页，打开就是工作台。
- 不使用大面积装饰渐变。
- 卡片只用于候选、消息、指标、审核门。
- 右侧 Inspector 始终可见，避免用户看不到 Angel 的依据。
- 文案以“状态 + 证据 + 下一步”为主，不写长教程。
- 颜色保持克制：深色侧栏、浅色工作区、绿色表示通过、琥珀表示待审。
